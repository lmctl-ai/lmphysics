# CI

Same shape as lmnum: five jobs (linux-x64 `ubuntu-22.04`, linux-arm64 `ubuntu-22.04-arm`,
macos-arm64 `macos-15`, macos-x64 `macos-15-intel`, windows-x64 `windows-2022` with choco MinGW),
each syncing pinned dependencies, installing `@lmctl-ai/lmctl@0.2.419` for `lmscript`, running
`./test.sh` with `LMPHYSICS_TEST_NETWORK=1` (the lmplot pipeline example downloads lmplot's release),
then uploading `lmphysics-<platform>[.exe]` plus LICENSE and THIRD_PARTY_NOTICES. A `v*` tag adds
the release job, which checks `--version` against the tag and attaches the binaries with `gh release`.

Measured job times (first green run, no cache): linux-arm64 ~6 min, linux-x64 ~8.5, macos-arm64
~9, windows-x64 ~10, macos-x64 ~15 (the slowest; Chrono core is 479 translation units).

## Platform issues found (all fixed without patching Chrono)

- `.gitattributes` with `eol=lf` is required: on Windows `deps.lock` otherwise gained `\r` and
  `git fetch` saw `<sha>?`.
- Sparse-checkout patterns (`/src/`) are rewritten by git-bash's MSYS path conversion; the
  `sync-deps.sh` sparse step therefore runs inside the directory with `MSYS_NO_PATHCONV=1`
  (`git -C` needs the conversion, so it cannot simply be set globally).
- MinGW cannot compile `chrono/utils/ChSocket.cpp` (array sized by a `const int` computed from
  `sizeof`); the socket sources are never used, so `cmake/Chrono.cmake` removes
  `utils/ChSocket*` from the `ChronoEngine` target on all platforms.
- Link `winmm` on Windows (HACD's micro allocator calls `timeGetTime`).
- A `workflow_dispatch` run with `only=windows-x64` cancels a push run in the same concurrency
  group; use it for fast single-platform iteration, then push a normal commit for the full matrix.
- Run logs of an in-progress run are not downloadable with `gh run view --log`;
  `gh api repos/OWNER/REPO/actions/jobs/ID/logs` works once that one job is finished.

From v0.1.3, both Linux builds use dynamic glibc >= 2.35. test.sh requires dynamic libc.so.6, allows only glibc library/loader names and rejects GLIBC symbol requirements above 2.35. Chrono/Bullet/Eigen and GCC C++ runtimes stay static; macOS/Windows policies are unchanged. No relink-object asset is generated.
